## 第二批 · 给业务页面提供离线组合包

37 份独立 JS 都内嵌了相同的 `glass-shader.js` 和 `glass.js`，这两个共享片段约 44.1 KiB。例如 `src/button.js` 是 260 B，独立按钮 JS 是 49,692 B。单独复制一个组件很方便，组合页面则会重复读取和解析这些片段。运行时已有共享场景和版本检查。

抽取按钮、输入框、下拉、数据表格、弹窗五个组件，在临时目录按现有画廊规则重新组合。JS 片段取首次出现，CSS 片段保留最后的层叠位置。以下为未压缩源码及逐文件 gzip -9 的体积，不含业务 HTML 和媒体。

| 五组件样本 | 独立引用，10 个文件 | 组合引用，2 个文件 | 降幅 |
| --- | ---: | ---: | ---: |
| CSS + JS 原始字节 | 462,842 B | 183,176 B | 60.4% |
| 各文件 gzip 后合计 | 123,323 B | 43,112 B | 65.0% |

两种引用方式均通过离线输入、键盘选择、表格排序、勾选、翻页和弹窗焦点归还检查。在 48 种外观组合中，对 6 个元素各抽查 7 项计算样式，结果一致。这里验证的是该五组件样本。[现有组合构建](../build.mjs#L144)

**建议投入 1–2 人日。** 从现有组件依赖表生成指定组件清单的一对 CSS/JS 与引用示例，沿用普通 `<link>` 和 `<script defer>`。以这五项做首个验收样本，再测有传递依赖的组合、已有独立包与组合包混用、加载顺序，以及业务 CSS 对主题令牌的覆盖。首个采用页面可以选同时包含筛选、记录表和详情弹窗的工作区。[组件依赖表](../build.mjs#L19)

## 第三批 · 减少预览首页为隐藏示例做的工作

首次以 `file://` 打开 `#switch`，桌面实测请求了 HTML、一个 CSS 和两个 JS，共 1,319,629 B，约 1.26 MiB。页面已连接 445 个 `ml-*` 元素，其中 8 个具有布局矩形，5 个在桌面视口内。共享玻璃场景登记了 249 个绘制回调。场景每次唤醒都会遍历这些回调，后续可见性检查会提前结束部分工作。249 是登记数。[预览初始化](../preview/preview.js#L212) · [场景遍历](../src/glass.js#L489) · [可见性检查](../src/control-glass.js#L64)

**建议投入 2–4 人日，先用两个栏目试点。** 将非当前栏目的实时预览与应用示例保存在 `<template>` 中，在首次访问时挂载对应控制器。离开栏目时解除渲染订阅，按需保留交互状态。先用 Switch 和较复杂的表单验证，再扩到其余栏目。保留原有 hash 深链、浏览器前进后退、代码复制和纯本地打开方式。

验收时在相同视口比较首屏已挂载元素、绘制回调和首次可交互时间，再往返切换两个栏目 20 次。首屏只应承担顶栏与当前栏目所需的实例；反复切换后订阅数应回到稳定水平，输入值、焦点和复制出的独立示例均须可用。启动体积与挂载量分别记录，模板化本身主要减少后者。

### 多线程、并发、GPU 与共享渲染的适用范围（2026-11-25）

本轮用同一交付版本做隔离对照，环境为 Windows、系统 Chrome 157、RTX 5070 Ti。长表测的是稳态呈现，贴图测的是两个首次请求从开始到均可解码的耗时。两类结果用于决定不同的改动。[逐轮数据与实验条件](../benchmarks/results/parallel-rendering-chrome-2026-11-25.json)

**共享渲染。** 同一文档已共用调度场景、WebGL 上下文和着色程序。渲染器把各组件的最终图像复制到各自的画布。125% 缩放、千行表格停在中段时，实际只有按钮、输入框、下拉框和表格四个玻璃前景。120 次指针输入共计 476 次 WebGL 绘制和 476 次输出复制，每个前景各 119 次，全部使用同一上下文和程序。指针停稳后抽查 300 ms，绘制与复制均为 0。另做四轮对照，在完整背景折射下临时跳过其余三个控件的前景绘制与复制，高档从 84.69 到 84.74 FPS。具备大量同时可见玻璃控件的页面，可以单独测批量绘制的收益。逐组件光源相对位置、按压状态和背景输入仍需保留。[渲染器](../src/glass-shader.js) · [场景与贴图缓存](../src/glass.js)
